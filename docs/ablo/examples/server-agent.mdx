---
title: "Server Agent"
---

Most server agents should import the app schema and use the same model methods
as the product UI.

```ts
import Ablo from '@abloatai/ablo';
import { defineSchema, model, z } from '@abloatai/ablo/schema';

const schema = defineSchema({
  tasks: model({
    title: z.string(),
    status: z.enum(['todo', 'doing', 'done']),
    summary: z.string().optional(),
  }),
});

const ablo = Ablo({
  schema,
  apiKey: process.env.ABLO_API_KEY,
  transport: 'http',
});

export async function completeTask(taskId: string) {
  await ablo.ready();

  // Claim grants exclusive, ordered access and hands back the fresh row.
  await using claim = await ablo.tasks.claim({ id: taskId });

  const updated = await ablo.tasks.update({
    id: taskId,
    data: { status: 'done' },
    claim,
    wait: 'confirmed',
  });

  return { status: 'done', task: updated };
  // claim auto-releases as the function returns
}
```

## Atomic batches

When several rows must change together, use the same schema-backed client and
submit one atomic commit:

```ts
await ablo.commits.create({
  operations: [
    { action: 'update', model: 'tasks', id: 'task_123', data: { status: 'done' } },
  ],
  wait: 'confirmed',
});
```

When two writers may touch the same row, `claim` serializes them and re-reads
the fresh row before the waiting writer continues:

```ts
await using claim = await ablo.tasks.claim({ id: 'task_123' });
await ablo.tasks.update({
  id: 'task_123',
  data: { status: 'done' },
  claim,
  wait: 'confirmed',
});
```

Keep the schema beside the worker. It gives reads and model writes one typed,
shared contract.
